地面站与真实设备接入规划 — 2026-11-11

1. 页面布局
地面站为主体：左侧机队/任务，中央二维三维地图与遥测条，右侧姿态仪、模式、控制按钮和设备状态。园区监控是辅助面板，不替代飞控台。小屏纵向滚动，不隐藏姿态仪。视频可放大；实时、历史、仿真、真机均明确标识。

2. 当前能力
仿真解锁、定点、自动、返航、降落、航线装订已实现。
GET/PUT /api/mavlink 已实现只读监听：心跳、system_id、解锁状态、经纬度、相对高度。真实姿态、电池、模式和指令尚未接通。收到心跳不会把按钮切换到真机；不可混合真实位置与仿真姿态。
监控画面为 Canvas 合成俯视图，无真实视频源或媒体网关。
新增 GET /api/device-integration 返回能力声明；下述硬件指令与视频会话路径只是预留契约，尚未实现。

3. 飞控适配
设备注册将 vehicle_id 与 system_id/component_id、连接配置、视频源引用绑定。按系统编号分流遥测，补齐姿态、电池、地速、GPS质量、模式。每项携带来源、采样时间、有效性与数据年龄；断链后标失效，不伪装正常仪表。坐标统一 WGS84，区分相对高度和海拔基准，禁止把仿真 ENU 直接发给真机。
预留 POST /api/hardware/{vehicle_id}/commands：command_id、vehicle_id、system_id、command、parameters、expires_at。
回执阶段 accepted/sent/acknowledged/rejected/timeout/unknown。HTTP 成功不等于飞控执行成功。实现鉴权、目标校验、状态校验、幂等及超时；结果不明时不盲目重发。航线上传采用协议握手。真机控制必须明确选择真实目标，不自动切换。

4. 视频适配
相机 RTSP -> 服务端媒体网关 -> WebRTC 低延迟播放，HLS 为兼容选项；浏览器不直接播放 RTSP。
预留 POST /api/video/{vehicle_id}/sessions：返回 session_id、vehicle_id、source、transport、播放/信令入口、expires_at、health。
凭据保存在服务端，不返回浏览器或写日志。飞控与视频分别显示连接状态、延迟和更新时间。吊舱姿态、拍照录像接口根据设备确认 MAVLink 或厂商 SDK，合成投影不作为真实反馈。

5. 实施与验收顺序
A 恢复仪表与地面站布局，提供接入能力声明（本轮）。
B 确认飞控型号/固件、串口或 UDP、system_id、相机型号/视频协议；先接只读完整遥测与测试视频。
C SITL 验证指令回执、航线握手、断链、超时、重复请求；再做无桨台架测试。真实飞行另行明确授权。
D 验证通过后启用显式仿真/真机模式，权限或链路不足禁用真机控制。
E 园区巡检、视频/预警时间对齐、操作日志和处置回放联调。回放不发控制命令。

待确认：飞控型号与固件版本、数传连接方式、相机/吊舱型号和视频协议、现有媒体服务、SITL条件、部署网络和操作用户。不要在聊天中提供密码或密钥。

2. 拖动时间轴自动暂停。仪表高度/速度/电量/姿态、二维位置、三维位置与姿态、截至该时刻的航迹全部使用同一条历史快照。采用不晚于游标时刻的采样，不伪造插值；记录间断超过 3 秒则标记缺失。
3. 播放到末尾自动停止；再次播放可从首帧开始。“返回实时”恢复最新遥测，不会发出飞行指令或恢复飞行任务。
4. 读取/回放期间锁定 SITL 操作，停止独立测试视频，明确提示没有同步录像。回放暂停只暂停显示，不会暂停正在飞行的仿真飞机。
5. 字段时效随轨迹采样保存。新记录中过期姿态不渲染成有效实时姿态；旧记录仍允许读取，但标注缺少字段时效信息。
6. 后端位置快照最高约 5 Hz，最多 5000 个采样。已完成巡检的记录不再被后续地面遥测覆盖；新上传巡检任务或重启 SITL 会清除该内存记录。前端一次读取后使用固定快照，不受随后实时轮询影响。尚未实现跨服务重启的历史档案管理。
验收包含暂停/拖动/返回实时、实时轮询不覆盖历史、异步读取后切换来源不误入回放、回放期间控制拒绝、记录时效与完成后保留等测试。真实浏览器视觉验收仍受浏览器控制禁用限制。
本轮结果：68 项 Python 测试、29 项 Node 测试通过。更新后实际 SITL 完成起飞、巡检、降落上锁，取得 749 帧、179.57 秒记录。生产回放适配器抽查 107 个时刻，位置坐标反算、姿态、仪表高度与航迹截止时间全部通过；落地后的接口记录与完成快照一致，未被地面遥测覆盖。报告保存在 outputs/ground-station-sitl/2026-11-12-twin-replay-acceptance.json 和同目录 twin-replay-check.json（带日期前缀）。

2026-11-12 持久化飞行档案（替代上节的“新任务/重启清除”限制）
- 原回放面板新增“历史飞行任务”选择框、刷新及分页。每条显示创建时间、区域、状态、帧数和任务编号短码；选择历史任务即加载其固定快照，可播放、暂停、拖动和返回实时。
- 即使 SITL 未启动，也能读取历史任务的坐标原点、计划航线、姿态与航迹，驱动三维飞机和仪表。历史回放不发送控制指令。
- GET /api/sitl/records?limit=30&offset=0 提供分页目录；GET /api/sitl/records/{id} 返回独立任务快照。任务编号不复用，不同区域或新任务不会覆盖旧记录。
- SQLite 元数据与逐帧数据以事务保存，约每 5 秒提交一次增量，完成任务及正常停止/切换任务时补存。记录保留各字段时效和独立坐标原点。内存最多 5000 帧的滚动窗口不再限制已提交的历史档案长度。
- 非正常进程退出后，尚未完成的旧会话标记为中断，不伪称完成；最多可能缺少最后约 5 秒尚未提交的数据。存储异常会写入 SITL record_error。
- 标准启动脚本将 FLIGHT_RECORDS_DIR 默认设为 platform/ubuntu/flight/data/flight-archives。当前服务使用该目录，数据库为 flight-records.sqlite3。可以用 FLIGHT_RECORDS_DIR 覆盖；直接运行 uvicorn 时应明确设置同一目录。
- 当前已有旧记录已迁入该档案库；重启 SITL、重启后端或新建任务均不删除档案。此版提供只读目录与回放，没有自动清理或删除历史记录的操作。
本轮验证结果：70 项 Python、30 项 Node 测试通过。新 SITL 巡检完成并落地上锁，持久化 750 帧、约 180 秒记录；重启整个后端（同时停止并重新启动 SITL）后，两条已完成档案的坐标原点、航线和全部帧的 SHA-256 校验值保持不变。随后创建东侧园区任务（仅上传、未起飞），再次核验旧档案不变。通过持久化 HTTP 接口取回的记录抽查 108 个时刻，三维位置、姿态和仪表数据一致。报告位于 outputs/ground-station-sitl/2026-11-12-flight-archive-*.json。浏览器视觉验收未完成。
可复验工具：scripts/test_record_archive.py --capture --baseline /tmp/records.json；重启或创建新任务后运行同一命令但去掉 --capture，校验已完成记录不变。默认接口为 127.0.0.1:8772。
