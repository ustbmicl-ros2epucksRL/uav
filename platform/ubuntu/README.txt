设计以 platform/docs/平台规划与设计.md 为准。当前网页只是说明，不是管理系统。

Ubuntu 服务器上的两套相邻系统。它们不替代感知网络规划平台，也不改变申报书的科学问题和考核指标。

组成
  规划平台    Ubuntu 容器，端口 8767。原有感知网络规划原型。
  飞控平台    Ubuntu 容器，端口 8772。飞机解锁、航线装订、自主飞行、返航和遥测。
  低空服务平台 Ubuntu 容器，端口 8771。飞行申请审批、任务调度、数据共享、事件、绩效和门户。

低空服务平台按三类使用方给出不同视图：各类门户只看已批准窗口，城市云脑看任务、事件和绩效，移动终端按飞手编号看自己的任务。飞行控制指令下发到飞控平台。梯级直播和 AI 智能识别保留接口，未接入机载视频，不返回识别结果。

测试
  在 platform/ubuntu 目录执行：sh test.sh
  单元测试和三平台联调都在 Ubuntu 24.04 容器内完成。
  联调通过的标准：批准一条园区场景申请，下发到 UAV-01，服务器推进飞控节拍后任务状态为已完成。

启动后页面
  http://127.0.0.1:8771  低空服务平台
  http://127.0.0.1:8772  地面站
  http://127.0.0.1:8772/network/  感知网络智能规划，与地面站同一端口
