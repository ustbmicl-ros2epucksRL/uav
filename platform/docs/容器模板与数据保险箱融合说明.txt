二、可融合的机制与必须保留的安全边界
原包：Template.content 定义模式；根/子容器用 _ord，表格用 _head；t/r/misc 表达类型、必填和约束。DataSet 将模板与数据集绑定。PostgreSQL 存元数据；Mongo 拆分根内容、容器、表格及行；ES 保存展开内容和检索摘要。
对应证据：README.md、mgedata/generic/template_fields.py、apps/storage/docs/data.py、apps/storage/models/data.py、apps/search/trans/data.py（均位于归档根目录下）。
适合复用的是数据结构及转换理念。现有保险箱负责身份、组织、授权、密文、审计和独立检查点；模板不能提供或覆盖 owner、subject、权限、账号或检查点版本。
原 ES 转换会展开内容字段并生成 summary，不应直接复制到保险箱。未获授权的搜索不得暴露内容、来源、样本和数量等敏感侧信息；检索副本不能作为授权依据。
Mongo 拆文档本身并不实现加密或防回滚。直接增加三个数据库将引入跨库一致性和备份回滚问题，因此当前未部署 PostgreSQL/Mongo/ES，也未把原数据库替换进现有平台。

三、本次已实现
1. 增加 container_contract.py，沿用 t/r/misc、根容器 _ord、表格 _head 的结构。
2. 固定版本 lowair-synthetic-features/v1，内容为 provenance 来源容器 + samples 特征表。当前支持字符串、有限数值、候选、表格、容器（t=1/2/6/8/9）；模板由服务端代码固定批准，浏览器不能自行注册模板、修改单位或映射逻辑。
3. 数据包包含 format、template_id、template_version、template_sha256、mapper、完整 template 和 content。版本/摘要/模板正文/映射器必须全部一致，拒绝未知字段、必填缺失、非有限数值、布尔数值和伪称现场验证数据。
4. 入柜前完成模板校验、数据去重一致性及至少三个独立分组检查，再将整个数据包通过已有 AES-GCM 机制加密保存。模板和来源均属于密文；资产摘要绑定整包，已由现有全状态检查点覆盖，无额外未保护元数据表。
5. 任务执行时先走登录身份、组织角色、用途、撤销/额度及检查点校验，再解密并重新验证容器合同，按固定白名单把 feature_1/feature_2、label、group_id 映射成模型输入。
6. A 的 dataset 输出包含分组隔离的训练/验证/测试集；B 的 stats 输出仅含原有质量统计。两者带模板摘要、版本、映射器及 synthetic 标识，但均不包含 provenance.source 文本。
7. 原 JSONL 资产仍可处理；原授权/账号数据库不需要迁移，不自动重签旧资产。新默认入柜使用容器包。
8. 页面新增“容器模板与 JSON 导入”：可下载固定模板合成示例，再校验上传。已有“合成数据加密入柜”继续可用。

四、接口与使用
GET /api/cabinet/container-template：登录后返回服务端合同和合成示例，不返回已有资产内容。
POST /api/cabinet/ingest：仅 owner 可调用，沿用 Cookie、CSRF、独立检查点保护。无请求体或空对象保持原合成入柜行为；完整容器包则校验后入柜。一个所有者仍限一个演示场景资产。
文件示例：research/data_security_cabinet/examples/lowair-container-v1.json。
页面文件上限和合同规范化后上限为 1 MiB；表格最多 10000 行。生产入口仍需限制原始 HTTP 请求体大小及并发，不能只依靠解析后的限额。
本版只接收固定低空合成特征数据，不接收原包中的钻杆模板；图片/文件/范围/数组/生成器尚未实现。不会下载 URL、读取本机路径、执行模板代码或自动转换物理单位。
未知或变更模板返回 422，不写入资产；账户、跨主体、撤销和检查点失败仍按既有 401/403/404/409/503 路径处理。

五、后续融合建议（尚未实现）
A. 模板注册与审核：在检查点保护的数据库内维护草稿/审核/发布/停用；发布版本不可覆盖。新字段、单位、处理器或输出范围改变必须生成新版本并重新审核。
B. 多模态大对象：将图片、视频、雷达等内容拆为独立密文对象，建立加密清单，绑定资产版本、模板摘要、容器路径、行号、对象摘要及算法版本；远端检查点提交清单。对象存储只能存密文，不能由请求传入任意路径/URL；下载必须重新鉴权。
C. 跨存储提交：先暂存密文并核对完整性，再提交受保护清单；未提交对象不可访问。旧对象、旧清单、旧索引任一回滚均应拒绝或重建，不允许以检索结果绕过主授权。
D. 检索：仅索引经审核的非敏感目录字段，索引只作候选定位；结果逐项回到保险箱按当前账号/组织/授权过滤。禁止照搬原 DataToEsDocument 的完整 content/summary。
E. 模型输入：为每个审核模板配置明确的特征/标签/分组映射，保留数据质量和处理溯源；多模态提特征需另做处理器和验证，不能将当前二维合成特征称为真实视频/雷达模型管线。
这些能力可以逐步吸收原包的容器组织和导入导出结构，不应把旧 visibility/public 字段直接解释为新系统授权。

六、验证和边界
模板校验、模板替换拒绝、未知字段、非法数值、重复 JSON 字段（密文包解码）、跨组冲突、来源文本不释放、A/B 输出隔离均有测试。平台测试验证非法模板不产生资产，普通主体不能入柜，来源文本不出现在数据库明文或结果中。

PYTHONPATH=platform:research/data_security_cabinet python -m pytest platform/tests/test_cabinet_demo.py research/data_security_cabinet -q

本次融合不增强宿主 root 隔离，也不改变独立检查点 CAS 成功但本地提交丢失时的安全锁定限制。仍需后续 TEE/远程证明/独立密钥服务验证。
