# 航路与云边端算法选型及复现

核查及接入日期：2026-11-13。保持现有地面站三栏布局与统一入口。

## 1. 本轮结论与完成范围

采用已有文献和开源实现，不提出新算法。当前交付是**开源算法组件复现 + 平台场景适配 + SITL 执行 + 本地多进程计算与回放**，不是论文全部实验、真实云边端部署或航路与卸载联合全局优化的复现。

- 航路：采用 OMPL 2.0.1 官方 BIT*；接入 2026 年 HATTO-UFog 的 ACS-DS 独立模块作近期论文对照；保留平台现有 A* 基线。
- 计算：采用 HEFT 原开源实现的排序与插入调度，适配机载端、两个地面边缘节点和云节点。HEFT 是 **2002 年成熟基线**，不是最新算法。近期论文项目经过源码核查后尚未获得完整、场景匹配且本机可复现的卸载实现，因此不把它们包装为已完成。
- 联动：规划结果沿弧长取 5 个位置，分别计算相同 DAG 在 HEFT、全部端侧、固定边缘、固定云端下的调度。结果驱动地图、三维预览、卸载流向、任务时间轴、节点占用和方案比较表。
- 实际执行：经区域申请审批和 SITL 准备后，可启动本地端/边/云独立工作进程，执行合成图像 DAG，记录实测时延、结果和重试；详见第 9、10 节。
- 存档：保存输入、场景快照、空域版本、地图锚点、源代码版本、输入摘要和输出；重启后可读取。算法实验记录与飞行档案分开，算法页面没有装订、解锁、起飞操作。

## 3. 原实现与适配的边界

### 航路

BIT* 直接调用官方 Python 绑定。每次计算在独立子进程中运行，设置随机种子；API 设置计算预算与超时，避免全局 RNG 污染并隔离 native 资源生命周期。BIT* 使用墙钟预算，固定种子不保证在不同机器/负载下输出完全相同的路径；应比较可行性和路径指标，归档保存实际输出。

平台提供 ENU 空间范围、起终点、膨胀障碍棱柱以及连续线段碰撞检查。建筑膨胀水平 20 m、垂直 10 m，禁飞区同时读取现有空域配置。算法只产生巡航段，尚未约束转弯半径、加速度或飞控动态，不自动转换为可执行任务。

ACS-DS 保留作者搜索逻辑，平台构造围绕障碍角点的有限可视图。仅修改相对导入，以及原可选回退分支中未定义的 `dist` 调用。作者代码无解时会返回起终点直线，适配器必须再次验证每个航段；不安全则返回 `no_path`，禁止将直线作为有效结果。没有把缺失的环境模块自行补写后宣称原论文复现。

### 云边端

HEFT 是异构任务 DAG 的静态启发式，不是新优化算法。沿用上行排序和最早完成时间插入调度，仅作以下工程修正：

1. Python 3 包内相对导入。
2. 原实现调用通信代价时交换源/目的节点的问题，改为方向正确，覆盖不对称上下行测试。
3. 接受恰好等长的空闲时间片。
4. 固定相同排名时的排序，保证确定性。

节点一个预留串行执行通道，计算需求单位 Gcycles，节点能力单位 Gcycles/s；通信数据单位 Mbit，链路速率 Mbps，时间单位秒。默认能力仅为示例参数，尚未通过任务机实测标定。任务依赖必须无环；编号必须唯一；禁止未知链路端点、非法数值。

以原有 HEFT 排序/分配函数初始化含既有忙碌时间的执行日历。虚拟输入与返回节点固定到机载端；入口数据从机载端传出，任务间按输出大小传输，叶任务结果返回机载端。方向链路用带宽/延迟计算传输时间，经可达中继的最短传输时延路径供 HEFT 使用。没有双向路径的节点不可分配。

基线“固定边缘”始终选择配置中第一个边缘节点，该节点不可达则报告不可达，不悄悄换成另一个站；固定云端同理。全部端侧仍使用同一 DAG 和端侧资源日历。

## 4. 当前模型限制（页面也显示）

- 静态算法实验中，每个航路采样点为独立静态批次，位置在该批次中固定。不是持续飞行中的任务迁移/调度，前一个采样点队列不会延续到下一点。
- 链路范围与预留速率是显式仿真输入，未把感知 SINR 冒充通信吞吐量；目前未做真实无线信道或遮挡衰落标定。
- 预留带宽假设下不模拟链路争用；节点只建模一个串行计算通道，不宣称 GPU/多核调度。
- 功率×计算时长给出的是**计算能耗**，不含飞行动力、传输、空闲或冷却能耗。
- HEFT 以完工时间为导向，不优化能耗、不保证截止期、也不保证优于每个固定部署基线。页面显示实际超期，不能把任务分配等同于按期完成。
- 地图云节点不画成雄安某个物理点；只显示机载采样位置、地面边缘位置和地面相关传输段。云端去向在任务分配和传输路径里查看。
- 未接真实远程 worker，未自动发给 SITL，更未发送真实飞控命令。

## 9. 区域任务—SITL—遥测调度联动（2026-11-13）

在同一地面站布局增加“生成区域任务申请”入口。实验的巡航段通过 `GET /api/algorithms/runs/{id}/mission` 补齐原点垂直起飞、进入区域、离开区域和返航落地航段；连接段沿用安全检查及绕障模块，不修改已批准航线。整条路线检查建筑安全包络、当前禁飞区、围栏、电量预算和最多 20 个航点。原点或空域版本变化时要求重新规划。

申请增加 `algorithm_run_id`，创建申请时后端核对完整路线及场景，审批后生成的业务任务保留 `area_id`、算法编号及输入哈希。SITL 验证/准备沿用原接口，复查坐标原点、当前空域、定位时效和未解锁状态。准备仅上传，不起飞。计算配置在准备阶段随执行绑定冻结，飞行档案保存这份配置。

SITL `GLOBAL_POSITION_INT` 驱动 ENU 坐标，每秒最多计算一次 HEFT 独立批次，使用规划时冻结的节点、链路和 DAG；不改变飞控航线。位置变化影响可达边缘节点、传输时延与任务分配。结果含采样时间、实验与执行编号、位置、任务时序和节点占用，并写入飞行记录。定位/GPS 数据超过 3 秒不作为有效实时调度，计算异常也不伪造成功结果。

右侧折叠项“云边端调度 · 遥测联动”显示当前任务分配和时延，地图同步显示边缘节点与卸载链路。回放读取遥测帧中保存的计算快照，跟随原有暂停、播放、拖动时间轴，不用当前计算配置重新推算历史；回放期间飞行控制锁定。SITL 停止或服务重启后仍能回放归档。

### 操作步骤

1. 统一入口 `http://127.0.0.1:8772/` → 航路与计算 → 选择区域及飞机 → 计算。
2. 点击“生成区域任务申请”，通过“查看申请与任务”进入原服务管理，批准申请并生成任务。
3. 在地面站启动本机 SITL；服务管理中依次“验证 SITL”“准备 SITL（不起飞）”，然后“查看执行”。
4. 地面站任务控制依次引导、解锁、起飞、执行；以 MAVLink 回执及遥测确认动作，不以按钮点击代表完成。
5. 展开右侧调度详情观察节点选择；任务完成后同步执行回执，从任务进入“结果回放”，拖动时间轴查看历史调度。

## 10. 本地端、边、云进程实际执行（2026-11-13）

### 运行模型与证据边界

在已有 SITL 任务绑定上提供“启动本地计算”，按计算配置创建独立 Python `spawn` 工作进程（默认 device、edge-a、edge-b、cloud 四个进程），用有界 IPC 队列传入任务及父任务输出，再回传结果。仅运行内置的五个固定任务：128×128 合成灰度图预处理、亮像素阈值统计、八区间直方图、统计融合、异常比例汇总。输入由该批次 SITL ENU 位置确定，输出可复算并保留 SHA-256。这里确有进程执行和数据回传，但不是机载视频目标识别，也不是实际部署到不同硬件或广域网的云边计算。

HEFT 继续负责节点选择，未运行任务按最新有效遥测重算可达节点，并用当前执行槽占用更新忙碌时间预算；正在执行的任务不迁移。配置的空间链路只用于派发资格检查，真实传输发生在本机 IPC，不能把本机测量值当成无线网络时延。节点额定计算能力、模型链路时延与 HEFT 预测结果仍明确标为模型值。

每 2 秒最多接收一个批次，同时最多 2 个批次；每节点一个执行槽。输入更新采用最新遥测，不堆积无限飞行帧队列。位置/GPS 数据超过 3 秒时停止新批次和新任务派发，已运行工作允许回传。每次任务尝试超时 3 秒，最多 2 次尝试；失败后退避，再在可达条件下回退端侧执行。进程崩溃或超时会终止并重建对应进程；依赖失败的下游取消，批次上限 15 秒。重试使用独立 token，迟到结果不得覆盖已结束或新一次尝试。

协调器运行在独立线程，飞控收包只投递遥测快照；不在 MAVLink 收包线程执行计算、等待 worker 或写计算证据。停止计算不发送飞行命令。飞行结束后停止接收新批次，等待已接收批次结束，再关闭工作进程；服务退出也回收进程。

### 实测指标

- `compute_s`：worker 内核的实测墙钟耗时；`cpu_s`：worker 进程实测 CPU 时间。
- `roundtrip_s`：派发至协调器收到回执的实测耗时，包含 IPC、序列化和轮询等待。
- `latency_s`：批次接收到最终汇总结果的实测端到端时延。
- `busy_fraction_10s`：最近 10 秒执行槽占用比例（从派发到收回），不是整机 CPU 利用率。
- 每次尝试保存 PID、节点、遥测时刻、派发位置、排队时长、失败原因、恢复策略和结果摘要。任务结果及取消/失败均不伪造成功数值。

### 接口、保存与回放

- `POST /api/compute/start`：传当前 `execution_id`，必须是已准备的算法 SITL 任务；同一个正在运行的执行重复启动不会创建第二组 worker。
- `GET /api/compute`：当前进程状态、负载、最近批次、重试与返回结果。
- `POST /api/compute/fault`：传 `execution_id`、固定任务名及 `fail/timeout/crash`，只注入下一次该任务派发。页面提供一次普通失败按钮。
- `POST /api/compute/stop`：停止计算并取消未完成工作，不影响飞机控制。
- `GET /api/compute/records/{record_id}/batches`：读取该飞行档案的批次与各次尝试。

证据保存在飞行记录数据库的 `compute_snapshots` 和 `compute_batches` 表，按飞行档案/执行编号关联。飞行档案读取时附带 `runtime_history`，回放使用时间轴上不晚于游标的实际执行快照；最后返回的结果即使略晚于飞行结束也扩展回放时段。旧档案没有 worker 数据时明确显示“此时尚无实际执行记录”。回放中的启动、停止、故障注入均禁用。

## 12. 实测反馈调度、节点掉线与任务迁移（2026-11-13）

继续使用已引入的 HEFT 排序与插入分配实现，只更换运行时成本输入，不声称提出新的调度算法。静态实验与历史配置基线仍按原配置求解；实际工作进程使用 `compute_feedback.py` 提供的成本矩阵。

- 每个任务/节点保存成功尝试的实测往返时间 EWMA（新样本权重 0.3），扣除该结果明确记录的模型冷加载时长，失败样本不当作正常耗时。首次使用本节点样本，否则使用同机其他进程的同类任务均值，再无样本则回退配置估计。跨进程均值仅适用于本机仿真，不作为异构硬件标定。
- 最近 10 秒执行槽忙碌率参与成本修正：`估计成本 = 基础均值 × (1 + 忙碌率)`；当前占用的剩余时间使用预计执行时长减去已耗时，不再以 30 秒故障超时作为排队时长。该负载系数是可解释的工程规则，未宣称最优或已证明性能提升。
- 按最新有效 SITL 位置检查配置链路可达性，HEFT 从在线候选计算进程选择任务节点。完成任务不会重新执行；每次实际派发保存修订号、候选成本/来源/样本数/负载、离线节点、前后节点、原因、遥测位置和输入帧哈希。`predicted_s` 表示这次反馈后的估计，实测时间仍单独记录。

### 掉线与恢复

`POST /api/compute/node` 请求包含当前 `execution_id`、`node_id`、`action: offline|recover`、`duration_s`（1–60 秒，默认 10）。仅操作本机工作进程，不操作飞控、网络设备或远程服务器。未知节点、错误执行编号、结束执行、非法参数被拒绝。

控制请求由协调线程处理：标记掉线、终止工作进程、将未完成尝试记为失败、排除派发候选并重试迁移。父任务输出和原始 JPEG 在协调器保存，因此无需等待原生产节点恢复就能继续下游；重试复用同一帧、使用新 token，旧回执不能覆盖新结果。这里仿真的是计算进程故障，端侧采集/协调器与逻辑网络网关仍在线，不能等同于整机断电或网络链路断开。

指定时长后自动重建进程，也可提前恢复。检测到意外退出/任务超时会隔离 1 秒再重建，避免立即重复向故障进程派发。本阶段每任务最多两次尝试（第 13 节更新为三次），耗尽后明确失败并取消依赖任务；全部候选不可用时等待恢复或批次截止，不伪造成功。模型随新进程重载，重新记录冷启动耗时。

## 13. 弱网、带宽变化与断链闭环（2026-11-13）

在现有 HEFT 与本地多进程工作负载之间加入 `compute_network.py` 应用层链路仿真。上传阶段结束才交给工作进程，结果回传结束才释放下游依赖。按实际 JSON 输入和输出字节数、配置链路带宽与单向时延计算等待；多跳采用逐跳存储转发，同一有向链路的并发传输均分容量。约 30 ms 协调循环推进，带宽变化影响在途数据，当前跳已进入的传播等待保留原值，下一跳采用新值。它不是 TCP/无线协议栈仿真，也没有修改操作系统网络。

`POST /api/compute/network` 必须绑定当前 `execution_id`。`profile` 为 `normal|weak|disconnected`；`duration_s` 为 1–60 秒，`mbps` 为 0.05–1000，`latency_ms` 为 0–3000。弱网对所有配置链路施加带宽上限和时延下限；断链关闭所有逻辑链路，端侧本地计算仍可进行。到期自动恢复，也可请求 normal 提前恢复。节点计算进程故障与链路故障分别控制，端侧协调器/网关始终存活，不模拟整机断电。

调度使用变更后的带宽、时延和当前 SITL 距离约束；在途路由断开时将该次尝试记为失败，使用原帧迁移重试。每个上传或回传阶段最长等待 8 秒，超时与工作进程 30 秒计算超时分开，网络等待不会误杀健康工作进程。为支持“节点掉线后又遇到断链”的叠加故障，当前默认最多三次尝试；耗尽后明确失败并取消依赖任务，不无限重试。所有候选不可用时等待恢复或批次截止。

各次尝试保存传输路径、字节数、开始/结束时刻、链路修订号、错误、`network_wait_s`、`worker_roundtrip_s` 和全流程 `roundtrip_s`。反馈 EWMA 只使用工作进程实测往返，扣除模型冷加载，不把人为链路等待混入算力估计。链路 profile、配置、在途传输与调度事件归档到 `runtime_history`；检测帧和输出继续按任务、执行、批次关联。回放游标仅读取当时已发生的快照。

保留现有布局，在右侧“云边端调度”→“节点故障演示”折叠区增加“弱网 10 秒”“断链 10 秒”“恢复链路”。详情显示链路配置和仿真等待，回放期间禁用故障操作。链路行的启停表示仿真 profile；实际传输另检查 SITL 距离可达性。
