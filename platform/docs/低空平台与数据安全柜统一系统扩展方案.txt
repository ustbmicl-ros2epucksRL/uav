低空平台与数据安全柜统一系统扩展方案
记录日期：2026-11-11
状态：架构建议与实施范围记录，尚未完成平台接入或硬件安全验收。

一、结论
建议扩展为一个统一的“低空感知数据可信应用平台”。统一用户入口、身份、场景、数据资产、任务及审计视图；后台保留业务平台、可信安全柜、独立密钥与证明服务、独立检查点服务的边界。
“一个系统”指产品和业务流程统一，不是把所有组件、数据库和管理权限放在同一台服务器。独立信任服务不能与被防护的计算宿主共用可被同一 root 控制的管理域。

二、现有基础及实际状态
1. 低空展示平台：已有 FastAPI 后端、地图与场景回放、感知网络规划、示范应用、异步计算任务、报告与导出。main.py 负责路由组合，core_api.py 负责场景和回放等接口，jobs_api.py 负责计算任务，demonstration.py 负责示范业务，store.py 管理本地数据库。
2. 安全柜研究原型：位于 research/data_security_cabinet，包含加密存储、多主体授权、固定任务加工、审计、Trustee 适配器、部署生成器及授权状态保护。
3. 授权状态保护：完整状态 HMAC、独立 HTTPS 检查点、版本比较更新、可信内存副本执行；具体故障语义与限制见 AUTHORIZATION_STATE.md。
4. 已完成的本地验证记录：42 项测试通过，包括 15 项状态保护测试；证明客户端契约测试使用替身。不能将其表述为真实可信硬件或 root 攻击验收通过。
5. 尚未完成：安全柜平台 API、统一身份接入、前端页面、现有回放和算法适配、真实 SNP/TDX 验证、生产级恢复与高可用。当前仍是独立原型，不是已经上线的统一系统。

三、统一系统的组成
A. 展示与业务入口：沿用低空平台，统一地图、回放、规划、示范、任务、数据资产与授权管理。
B. 业务编排服务：处理身份会话、资产引用、任务调度和状态展示；不作为敏感数据最终授权裁决者。
C. 可信安全柜服务：独立验证身份及授权，在可信环境中解密、加工、运行算法和审核交付。
D. 密文数据存储：保存原始数据及敏感加工结果。
E. 独立信任服务：Trustee KBS、AS、RVPS，负责密钥资源与硬件证明；检查点服务负责授权状态的最新版本锚定。

四、数据与数据库分工
平台数据库：场景、页面配置、资产编号、任务状态及允许缓存的结果摘要。
安全柜受保护状态：身份映射、授权主体与用途、期限、额度、撤销、数据版本、任务及产物关系。
密文存储：原始数据、加工数据与敏感结果。
检查点服务：最新版本和完整状态摘要，不与计算节点同步回滚。
密钥服务：独立管理密钥资源，按可信环境策略发放。
关联关系：scene_id → asset_id + version → grant_id → cabinet_job_id → artifact_id。
平台侧“已授权”仅是显示状态，安全柜必须自行验证身份、授权和检查点，不信任前端自报 user_id。

五、接口与功能扩展建议
新增平台安全柜路由和服务适配层，负责资产登记、授权申请/授予/撤销、任务提交/查询、产物读取及审计查询。接口名称和路径在实施时确定，本文件不表示已有这些接口。
现有 core_api.py 的回放和报告、jobs_api.py 的任务和导出、demonstration.py 的示范运行需要接入安全柜任务与资产引用。
现有计算类型 volume、plan 与安全柜任务 stats、dataset 含义不同，需要显式映射和新的任务契约，不能直接替换。
安全柜现有 JSONL 特征加工器还需增加平台标准化量测格式校验、时空字段映射及算法适配；保持仿真真值不进入跟踪输入。
受保护数据必须关闭旧的直接读取与导出路径，避免新增安全接口后仍可从旧接口绕过。

六、前端展示建议
统一增加“数据安全柜”入口，提供数据资产、授权使用、安全任务和审计记录四个视图；原有地图与任务页关联相应资产、版本和授权。
显示实际状态：软件演示、远程服务连接、硬件证明结果、授权状态校验及拒绝原因；不得用固定绿色标志代替验证。
已发送到浏览器的数据即视为向该用户披露；隐藏下载按钮不是数据保护。无原始数据权限者只能取得允许的统计、脱敏或汇总结果。
普通后端若能读取明文，该后端 root 仍可能窃取数据。敏感上传应直接进入可信接入端，敏感计算与解密进入可信环境。

七、第一期建议范围
以一个示范场景为最小完整流程：
1. 导入一份标准化量测数据，加密入柜并登记资产版本。
2. 给 A 主体授权航迹分析，给 B 主体授权区域统计。
3. A 查看获准航迹，B 仅取得汇总，两者引用相同数据资产。
4. 任务、用量和交付产物均可追溯。
5. 撤销 A 后，后续请求及导出被拒绝。
6. 恢复撤销前数据库快照，系统检测不一致并停止受保护访问。
第一期先用明确标注的合成数据完成平台功能接入；演示模式不得宣称防宿主 root。

八、分阶段推进
阶段 1：统一身份及数据契约，增加资产/授权 API、任务适配和前端入口，打通合成数据流程。
阶段 2：接入标准化量测回放与分析，覆盖结果展示、导出和旧接口封堵；验证主体隔离、撤销、额度及状态篡改/回滚。
阶段 3：部署真实 SNP 或 TDX 可信执行环境，独立部署密钥与检查点服务，验证镜像和执行策略、端到端数据路径及宿主 root 攻击。
阶段 4：根据实测补充性能、数据规模、恢复、高可用、密钥轮换与运维；GPU 和原始视频/雷达处理另设验证范围。

九、验收边界
产品验收：同一入口完成入柜、差异授权、受控计算、结果交付、撤销和审计。
接口验收：直接调用 API、修改主体标识、访问旧接口、跨主体读取和导出均不得绕过权限。
状态验收：授权篡改、旧快照、检查点异常及并发分叉均按约定拒绝或锁定；明确恢复流程。
安全验收：只有完成真实硬件证明、信任链和攻击验证后，才能在限定威胁模型中描述防宿主 root 能力。
独立检查点及密钥服务的管理员仍属于可信范围；若攻击者控制并回滚整个信任域，本方案不能保证防回滚。

十、当前确认
本次仅记录并确定“统一产品、分离信任边界”的扩展建议，没有修改平台业务接口或启动部署。后续实现以本记录为范围基线。
