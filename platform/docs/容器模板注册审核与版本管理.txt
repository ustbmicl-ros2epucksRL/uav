容器模板注册、审核、发布与版本管理（2026-11-12）

1. 实现概况
当前平台保留固定模板/旧 JSONL 资产兼容，同时新增组织内模板注册表。模板定义、版本、审核人、生命周期状态，以及资产到模板版本的绑定，均在 persistent.db 内并纳入原完整状态 HMAC/独立 HTTPS 检查点。
模板定义不含数据所有者、账号、权限凭据或可执行代码。授权始终绑定具体资产和主体，不绑定“最新模板”。模板不提供直接读取原始数据的接口。

2. 生命周期与权限
草稿 draft → 提交 submitted → 审核通过 approved → 发布 published → 停用 retired。
提交状态也可被审核拒绝 rejected。被拒绝或已发布版本不能编辑；作者重新注册为下一版本后重新审核。没有删除版本、覆盖已发布版本、修改摘要、重新启用停用版本的 HTTP 接口。
owner 或 org_admin 可为本组织注册新模板或新版本；只有该版本作者能提交。审核、拒绝、发布、停用均要求本组织另一名 org_admin，作者不能自审自发。审核人与发布人可为同一名管理员，但必须不同于作者。若由管理员起草，需要另一名管理员审核。
只有本组织可以管理或按其发布版本入柜。接收方仍可由资产所有者显式授权为其他组织账号；这不会开放对方的模板目录、草稿或其他资产。模板发布不是资产授权。

3. 版本冻结与安全规则
每次注册保存完整不可编辑定义，并生成 SHA256；同模板 ID 的新版本号自动递增。审核、发布均针对该确切版本及摘要。草稿也不可原地修改，以免提交/审核期间被替换。
注册包必须仅含 definition 与可选 template_id。definition 包含 name、schema、mapping、purposes、data_kind。摘要覆盖全部定义，包括字段单位、顺序、处理器、输出用途和数据种类。
注册模板资产包格式：
{
  "format": "cabinet-registered-container-v1",
  "template_id": "服务端分配的模板ID",
  "template_version": 1,
  "template_sha256": "该版本返回的digest",
  "content": { "...": "符合schema的内容" }
}
资产包不能自带替代模板、权限、执行脚本或任意处理器。入柜检查组织、发布状态、版本摘要、数据类型及模型分组质量；资产和 asset_templates 绑定在同一受保护事务中写入，失败不留下半入柜记录。
每次授权检查模板允许用途；每次任务和已有结果读取都在原授权事务内重新检查模板状态。停用后不再允许入柜、新授权、执行或读取相关已有结果。结果已经交付到客户端的部分不能收回。
发布 v2 不改变 v1 资产和 v1 输出映射。v2 数据入柜产生另一资产 ID，需要重新授权；v1 的额度、撤销和授权不会转移。模板允许 dataset 也不能使 stats 账号升级为 dataset；模板能力、账号角色、资产授权三项必须同时满足。
直接修改定义/发布标志/绑定表，或恢复停用前快照，均被独立检查点拒绝。不能通过“缺表自动创建”或自动重签来恢复。初始注册表由离线显式迁移创建。

4. 数据类型与受控处理器
字段沿用容器格式 t/r/misc：字符串(1)、有限数值(2)、候选(6)、表格(8)、嵌套容器(9)。容器用 _ord，表格用 _head。未知字段、未声明顺序、类型错误和不支持扩展均拒绝。限制嵌套深度 8、字段总数 128、模板定义 64 KiB、规范化数据包 1 MiB、每表最多 10000 行。
数据种类 data_kind 可为 synthetic 或 observed。observed 仅表示提交方声明为观测数据，不代表经现场验证或质量认证；系统不自动判断真伪。界面提供的两套示例均明确标记 synthetic。
受控处理器只有：
- numeric-table-v1：显式指定顶层样本表、数值特征列、标签列与分组列。特征列必须为必填数值，标签/分组为必填字符串或候选。支持 dataset 和/或 stats。dataset 至少需三个独立组，按原分组隔离方式输出训练/验证/测试集，不输出其他来源字段。
- record-summary-v1：允许不同嵌套记录/表格结构，只支持 stats，返回存在字段数、表格数、表行数，不返回字段值、序列号、来源文本或原始记录。
不支持运行模板脚本、表达式、SQL、任意 Python、URL 抓取、附件下载或自动单位转换。图片/视频/文件、大对象分块和真实多模态特征提取尚未实现。
审核人需检查字段与单位、映射选择、标签/分组是否合理、允许用途与数据暴露范围。选择输出列属于审核责任，不能仅凭字段名认为已脱敏。

5. 前端操作
登录后所有者和组织管理员可见“容器模板与版本管理”。
A. 所有者载入“特征样本定义”或“设备记录定义”，可编辑定义 JSON；模板 ID 留空，注册草稿。
B. 点击该版本“提交审核”。独立管理员登录后刷新，查看定义，然后审核通过并发布；不合理的版本可拒绝。
C. 所有者在“按已发布模板录入数据”选择确切版本，填写内容 JSON，绑定版本加密入柜。示例按钮会填充对应合成内容；若修改了 schema，需同步调整内容。
D. 按原界面选择资产、用户名和用途进行授权。A/B 用自己的账号执行任务和查看自己的结果。
E. 修改模板时选择“查看 / 创建新版”，编辑 JSON 后注册；服务器分配下一版本，重新提交审核发布。旧版本及旧资产不被覆盖。
F. 管理员可停用发布版本；停用不可通过页面反转。
资产展示包含 template_binding，结果包含模板 ID/版本/摘要、处理器和 data_kind；不会依赖“当前最新版本”解释旧资产。

6. API
GET /api/cabinet/template-examples：已登录用户取得两套合成定义与内容。
GET /api/cabinet/templates：列出本组织版本；所有者/管理员可见草稿，其他角色仅见已发布版本。
POST /api/cabinet/templates：注册完整 definition；可选 template_id 表示为现有本组织模板注册下一版。
POST /api/cabinet/templates/{id}/{version}/{submit|approve|reject|publish|retire}：受控状态转换。
POST /api/cabinet/ingest：支持上述注册资产包，同时兼容固定模板。
全部接口沿用 Cookie、同源/CSRF、账号组织状态和独立检查点校验。模板接口未迁移时返回 503；非法定义/数据返回 422，非法状态转换返回 409，越权/未发布/停用/摘要不匹配拒绝访问。无 PATCH/PUT 编辑已保存版本的接口。

7. 部署与升级
在原独立检查点配置及账号系统已经就绪的前提下，停止平台所有 worker。沿用原 namespace、state.key 和持久数据目录，不要重新 provision 检查点，不要删除旧数据库。
从 platform/ 目录，用既有虚拟环境执行：
export SENSE_CABINET_CHECKPOINT_CONFIG=/etc/sensing/cabinet/platform.json
export SENSE_DATA_DIR=/var/lib/sensing
python -m app.cabinet_admin migrate-templates
此操作在先验证完整状态后创建 container_versions 与 asset_templates，纳入远端 CAS；不修改旧资产、不自动为旧资产分配新版本，也不重签不匹配快照。重复迁移被拒绝。
首次部署先按账号部署说明执行 migrate-auth、建立组织/账号，再执行 migrate-templates。确认至少有一名独立的组织管理员可审核所有者提交的模板。
随后沿用 HTTPS/同源/Secure Cookie 部署启动平台。反向代理限制 HTTP 原始请求体及并发，避免仅依靠解析后大小限制。当前为单机文件锁与独立检查点原型，完整数据库状态校验不提供高吞吐承诺。
升级无须新建 namespace；旧固定模板保留兼容路径，并非可用其修改注册资产。对固定示例重新入柜也只能产生不同资产，必须另行授权。
