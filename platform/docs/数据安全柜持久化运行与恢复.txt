数据安全柜持久化运行与恢复（2026-11-12）
本说明替代《数据安全柜独立检查点部署与验收》中“一份配置一个会话、重启失效”的限制；证书和外部检查点部署步骤仍适用。

一、实现范围
一个独立 checkpoint namespace 对应一个持久安全柜数据库，支持最多 1000 个未过期会话。每会话仍是一份合成资产、所有者及 A/B 两主体。多个浏览器/浏览器配置文件可同时使用各自会话，不需要为每个会话创建检查点。
平台使用 SENSE_DATA_DIR/cabinet-demo/persistent.db，包含身份、资产、授权、结果、审计以及 platform_sessions。所有表与 schema 均纳入同一个完整状态 HMAC/远端 CAS，不另设未受保护的授权索引。
会话表保存 cookie 的 SHA256 摘要、AES-GCM 加密的主体凭据、30 天到期时间。会话创建及三主体登记在一次受保护事务中提交；资产、授权、结果关联从已校验数据库重建，因此业务提交后进程退出不会丢失内存映射。
数据 KEK、审计密钥、操作者令牌、会话加密密钥从已部署的 state.key 以包含 namespace 和用途的 HMAC 分域派生；重启不重新随机生成。修改/丢失 state.key 会拒绝恢复，不能用新密钥替换。

二、启动与恢复
1. 在独立主机运行 prepare_checkpoint.py，为本持久系统分配一个全新的 namespace；启动 checkpoint_service.py。旧单会话数据库不自动迁移或重新签名，保留旧环境只读归档。新 namespace 是新系统，不继承旧资产的权限或撤销状态。
2. 受控配置 ca.pem、token、state.key、platform.json。文件权限 0600、父目录 0700；配置、凭据不进仓库。JSON 的 namespace/URL/文件路径需保持稳定。
3. 使用本机持久磁盘，禁止 /tmp、iCloud 同步目录、NFS 或多节点各自拷贝数据库。例：
cd platform
SENSE_CABINET_CHECKPOINT_CONFIG=/etc/sensing/cabinet/platform.json SENSE_DATA_DIR=/var/lib/sensing SENSE_CABINET_SECURE_COOKIE=1 bash scripts/run.sh
SENSE_CABINET_SECURE_COOKIE=1 用于 HTTPS 反向代理部署；本机 HTTP 联调不设置。反向代理应保留 Cookie、禁止缓存 /api/cabinet-demo/*，不要开放跨域凭据读取。
4. 首次新建会话仅在本地数据库不存在且远端 head 仍为空时初始化。已有数据库每次打开先验证当前远端摘要，既不重建授权表也不重置远端版本。
5. 平台正常重启后，同一浏览器的 HttpOnly/SameSite=Strict cookie 保留。页面自动请求 /api/cabinet-demo/resume，服务端校验完整状态及独立检查点时间后恢复角色凭据。结果、撤销和额度保持原值。凭据只进入页面内存，不写 localStorage。
6. 会话 30 天到期后不能恢复；过期数据不会被自动删除或重新激活，需新建会话。授权仍独立执行 30 分钟期限及 5 次额度。当前未实现生产登录、找回 cookie、延期和过期资产清理。

三、并发与隔离
同一主机/同一数据目录的 worker 通过 platform.lock 的 flock 串行保护完整 API 请求，竞争返回可重试 503，避免两个 worker 同时推进远端后覆盖本地。文件锁由进程退出自动释放。建议单 worker；此方案不提供多主机高可用或高吞吐承诺。
各会话具有不同身份，资产/授权/审计只显示本会话数据；请求体 role 不能替换认证主体。cookie 属于演示控制台，会话持有人可恢复该会话所有演示角色，不等同跨组织真实身份认证。不同浏览器隔离体验不同会话；同一浏览器新建会话会替换当前 cookie，旧会话仍存储但不会出现在列表里。
同一数据库共享保护边界：发现任意会话数据被篡改时整体拒绝，而不是忽略异常继续服务其他会话。

四、防回滚与故障恢复边界
恢复撤销前/额度消费前数据库快照、修改会话有效期或主体关联、删除数据库，都不能使旧权限生效。只要远端 head 已推进，本地缺失不会触发重新初始化。缺少配置且发现持久数据库时拒绝软件降级。错误配置/断连返回 503；状态不匹配返回 409。
数据库快照备份必须在停止所有写入/持有独占锁时完成，并记录独立 head；禁止在平台创建常规数据库文件副本后直接覆盖在线文件。恢复时必须匹配独立服务当前摘要；过期备份不能恢复服务。
远端 CAS 成功但本地提交失败仍会安全锁定。当前没有分布式原子提交、自动追赶、管理员强制重置或自动解锁。发生这种故障，应保全两端状态并调查，仅恢复经独立核验且与当前 head 完全匹配的本地状态；如果没有该状态，不能通过回退远端数据库恢复。
独立检查点不能与平台一起回滚。检查点主机持久磁盘、备份与管理员必须在独立可信管理域；单节点检查点本身没有防管理员回滚或高可用保证。
本期仍是软件控制面：有宿主 root 的攻击者可读本地密钥/进程、替换代码，因此不宣称真正防 root。生产防 root 需 TEE、远程证明、独立密钥服务及可信执行授权路径。

覆盖：两个会话身份/资产/审计隔离；新 FastAPI 应用恢复；独立 Python 新进程恢复 cookie 和已有结果；重启后额度耗尽仍拒绝；撤销仍有效；旧快照拒绝；删除数据库拒绝重新初始化；会话表篡改拒绝；移除配置拒绝降级；检查点断连拒绝；文件锁竞争返回 503，释放后可恢复。
首次初始化后补充会话表的跨事务窗口发生故障时，也会拒绝缺表数据库，不自动升级旧结构。代码升级/表迁移需另做受控迁移流程。
本轮未执行浏览器视觉验收或真实 TEE 测试。测试中的重启与攻击不是现场部署指标。
