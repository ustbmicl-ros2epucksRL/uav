示范应用基础平台：简明设计与验收
更新：2026-10-08
注：本文页码按 8 月预申请 PDF；现行依据为正式申请书 end-1124，页码见 app/proposal_source.py 和"申报书对照与完善边界.txt"。

定位与依据
以研究任务四的平台能力为载体，先支撑研究任务五的示范应用，
为研究任务一至三提供场景、部署、模型结果和评价证据的统一载体。
依据根目录主 PDF 申请书，采用 PDF 文件页序：
第 26–30 页：五个研究任务；第 43–46 页：平台架构及三场景示范；
第 15、19 页：至少三场景、至少五类示范任务。
原五页规划流程保留；“示范应用”包含总览＋三个专属场景页，共九个业务页面。
地面站顶栏和规划导航均可直接进入示范应用。

三个场景的独立入口（挂载在地面站时加 /network 前缀）
/demonstration：总览；显示场景任务数、试验数、配置在线设备数、实测/合成记录数。
/demonstration/electromagnetic：抗干扰；SNR 分布、定位测速、干扰条件描述对比。
/demonstration/corridor：道路；跨站设备集合变化、身份保持记录、参考航迹缺测区段。
/demonstration/urban：建筑区；三维建筑、冻结方案覆盖对比、融合模态与缺测恢复。
各页仅选择本场景规划任务，分别保存最近查看任务；原试验记录继续可用。
可一键建立对应场景的规划任务，再进入站址配置与规划页面；创建的是合成初始场景。
覆盖图基于冻结模型和计算网格；存在关联规划方案时可切换补盲前后配置。
不同干扰条件通过单独的“描述对比”入口比较，明确显示条件并提示不能直接归因。


申请书研究点 → 实现
1. 三维覆盖建模：复用已有场景、建筑、站址、设备、覆盖/盲区展示；
   示范任务冻结环境与部署快照；外部覆盖模型结果可按版本归档。
2. 干扰与多站协同：记录试验电磁环境等控制条件，接入多设备来源；
   分来源输出信号质量、定位与测速误差，支持同条件、共同样本对比。
3. 按需规划与多目标优化：关联已有规划任务及候选/确认方案的历史快照；
   试验可选择快照内的实际使用设备子集，用于基准/补盲配置对比。
4. 运行数据汇聚与模型修正：独立接入飞行真值、感知输出、设备状态、
   告警、策略及回执事件；质量校验后保存；生成可追溯的残差反馈；
   用按时间前半段估计的 XYZ 偏差生成校正候选，后半段留出验证。
   候选附源数据摘要、来源、模型版本和改善/未改善结论，不自动上线。
   协同跟踪与预警：统一回放导入航迹及事件，复用既有工作台融合/跟踪/规则基线。
5. 示范应用：支持复杂电磁区、物流道路、建筑区三个场景；
   提供抗干扰、定位测速、跨站跟踪、补盲、融合识别五类任务标签。
   五类标签是试验组织能力，实际示范完成情况由导入实测证据和现场验收决定。

操作流程
1. 在“规划任务/资源配置”建立场景及设备；需要时生成方案。
2. 从“示范应用”进入相应场景，再创建任务，填写验证目的、飞行/环境条件、坐标基准、
   真值来源及评价阈值，选择当前部署或规划方案；保存即冻结快照。
3. 载入合成示例试用，或导入统一 JSON；支持每任务多次试验。
4. 选择试验和来源，进行二维/三维、按目标、按时间的联合回放。
   已缺测航段不连线；在线/离线事件驱动相应设备显示状态。
5. 查看误差、样本检出比例、分类、连续性、延迟、重捕获和信号质量；
   比较基准/对照；生成离线校正候选；导出证据 JSON、残差 CSV 或打印。

数据规则
- 规划任务、示范任务、试验分别管理；示范任务/试验记录创建后不覆盖修改。
- 修改资源不会改变历史快照。新一轮条件或部署可建立新的示范任务。
- 坐标单位为米，范围 X/Y 0–2000、Z 0–300；超域数据拒绝，不能截断充当有效点。
- coordinate_frame 必须精确一致；平台不自动推断测绘坐标转换或时钟同步。
- t 为同一试验起点后的秒数；导入前需对齐设备时钟。
- source_id 区分原始设备或融合输出；target_id 是外部事后评价关联标签，
  不会传给跟踪算法作为输入。track_id 保留各来源的航迹身份。
- 设备必须属于冻结部署；重复目标/来源时间戳、非法范围、接收早于观测、
  非有限数值、错误模型输入摘要均拒绝，失败时不产生部分记录。
- 当前按批接入统一位置/航迹数据，不提供雷达原始回波处理或新增硬件驱动。
- 每批最多 10000 参考点、30000 观测点、3000 事件、50 来源、100 参考目标。
- 地面站 /api/vehicles/{id}/track 当前返回仿真记录。界面读取后将其标为
  synthetic，按第一个时间戳归零，清除原感知数据，要求用户另行导入并对齐。
  当前读取功能不发出飞控命令。实际飞行/RTK 记录可经统一 JSON 手工导入。

评价口径
每来源、每目标独立，在配置的时间容差内最近时间一对一匹配。
样本检出比例＝匹配参考样本/全部参考样本，仅代表本次航迹采样，
不代替空间覆盖率、严格探测概率或项目 90%/95% 空间覆盖要求。
定位 RMSE 为匹配样本三维距离均方根；测速及分类需要双侧对应字段。
缺测、超出最大间隔或 track_id 改变会中断连续段；单点时长为零。
重捕获从首个缺测参考时刻算至恢复，未恢复末尾不参与均值。
站点集合变化不等于跨站成功率；未匹配观测不等于虚警率。
时延为 received_t−t，需要共同时间基准；无样本返回空值。
对比要求同任务、相同参考轨迹、相同数据性质、实际控制条件、坐标和关联方法；
部署子集、配置名称、模型版本可变化。另列共同匹配样本定位 RMSE。
校正候选只验证固定偏差的留出效果，不替代复杂传播/协同模型或独立外场标定。

文件与接口
app/demonstration.py：任务、数据校验、评价、对比、校正候选及报告。
static/demonstration-overview.html / demonstration-overview.js：三场景总览。
static/demonstration.html / demonstration.js：复用组件构成三个独立场景页面。
static/portal-map.js：复用三维场景，增加独立轨迹及断点显示。
API 前缀 /api/demonstration；挂载时 /network/api/demonstration。
POST /trials；GET /trials、/trials/{id}。
GET /trials/{id}/template?variant=baseline|improved。
POST/GET /trials/{id}/runs；GET /runs/{id}、/runs/{id}/report。
GET /compare/{基准run_id}/{对照run_id}。
POST/GET /runs/{id}/calibrations，POST 参数 {"source_id":"fusion"}。
完整请求模型也见服务 /docs 中 Demonstration 相关路由。
外部算法结果位于 algorithm_results，包含 research_task、name、version、
input_digest（任务 snapshot_digest）、summary、metrics；提供版本化结果归档，
不宣称已执行该外部算法。

验证
后端覆盖三场景闭环、快照不变、错误输入原子拒绝、最近时间一对一匹配、
缺失字段空值、同条件比较限制、共同样本、外部算法来源和校正候选留出验证。
真实 Chromium 覆盖页面操作、JSON 文件导入、时间轴、三维回放、对比、下载、
刷新持久化、桌面和手机布局，并检查控制台错误。
测试：platform 下 .venv/bin/python -m pytest tests -q。
浏览器：项目根目录 node platform/tests/accept_demonstration.cjs。
浏览器默认连接隔离服务 127.0.0.1:8879/network，禁止用于生产服务。
该脚本会创建独立测试记录，在确认 in-process simulator 且无 MAVLink 指令后，
操作验收服务的 UAV-02 仿真对象生成日志并验证读取，不接触真实飞机。
验收结果：outputs/demonstration-acceptance/acceptance.json 和 验收报告.html。
